# CodeTrail v0.2 用户指南

CodeTrail 用来帮助你回答三个问题：**这个功能由哪些代码实现？Agent 这次改了哪里？我上次读过的内容还与当前代码一致吗？**

应用不会替你判断所有业务逻辑是否正确。你来定义功能、选择证据并确认阅读结论，工具负责定位、保存和发现直接证据的变化。

## 1. 第一次打开

普通使用直接从 [首页下载表](../README.md#下载) 选择 Mac 或 Windows 安装包，按 [安装说明](../README.md#安装) 安装并打开 CodeTrail，无需先安装 Rust 或 npm。源码开发方式见 [技术与开发说明](TECHNICAL_GUIDE.md)。

桌面窗口会先显示 **“演示项目”**。它用于熟悉界面，标注只保存在本机 WebView 中。要读取真实源码，点击右上角 **“打开仓库”**，选择项目目录；需要 Git 改动比较时选择仓库根目录。

项目已有功能关联时可以直接选功能阅读；带概览时先看模块和运行路径。没有功能关联时仍可浏览文件，推荐让编码 Agent 按 [交付协议](AGENT_DELIVERY.md) 建立关联，再在阅读器中刷新。阅读器不会自动推断项目的业务功能。

开发者若希望创建真实 Git 练习工程，可在源码目录执行 `npm run demo:init`，再打开新建的 `demo-workspace/`。脚本不会覆盖已有目录；需要另一份时使用 `npm run demo:init -- /absolute/path/to/another-new-demo`。

## 2. 选功能 → 读代码和改动 → 确认已读

左侧直接选择功能。中间先显示功能说明，用“阅读片段”切换跨文件证据，并查看这段代码的职责。当前文件有改动时默认展示“本次改动”；“完整代码”可查看上下文。读完该功能后，点击标题旁的“确认已读”。确认不会要求逐个点击片段，阅读完整性由读者判断。

右侧默认显示「Agent 动态 / 我的批注」；「更多 → 查看详情」可临时切换为详细证据。数据格式、功能 ID、人工审阅记录和底层能力保持兼容。

| 次级入口 | 保留的用途 |
| --- | --- |
| 左侧“浏览文件与改动” | 按文件或变更导航；“功能”切回功能列表 |
| 搜索下方“筛选” | 展开“只看改动相关” |
| 阅读区“更多” | 查看详情、相关逻辑、新建人工功能、绑定当前片段及导出 |
| “更多 → 查看详情” | 查看所有证据、旧人工功能编辑与修复、文件结构、反向功能定位及最近确认时间 |
| 详情内“关联信息 / 交付详情” | 按需展开稳定 ID 和 Agent 协议状态 |
| “本次改动 → 对比设置” | 指定比较版本，切换统一或并排差异 |

底部提示仍可展开查看被跳过的文件与分析限制。Agent 管理的证据不显示不可用的编辑和解绑按钮；应由 Agent CLI 更新。

## 3. 创建第一个功能

推荐按你要理解的行为命名，例如：

- 模型路由：哪些请求走本地模型，哪些走云端模型？
- 流式降级：已经输出 token 后，是否仍会切换提供方？
- 上下文管理：哪些消息会被保留或裁剪？

点击“更多 → 新建功能”，填写名称、说明、颜色。说明中可以写下你正在验证的行为和阅读疑问。不要为了覆盖每个函数而强制归类；公用工具函数暂时未绑定没有问题。

创建功能会保存 `.reader/` 元数据，不会修改任何源码。一个功能可以包含多个文件中的多个代码片段，也可以将同一片段分别绑定到多个功能。

## 4. 绑定整个函数或几行代码

### 绑定整个符号

1. 在左侧“代码”中打开文件。
2. 将光标放入目标函数、类或其他已识别符号；也可以从右侧符号列表跳转。
3. 不选择单独行范围时，点击绑定按钮会优先使用当前最内层符号。
4. 在对话框中核对目标功能、文件和行号，填写片段备注，确认绑定。

### 绑定局部片段

1. 在 Monaco 中选择需要阅读的代码行。
2. 点击“绑定代码片段”。
3. 核对行范围并确认。

片段按 **1 起始、包含结束行** 保存。选区覆盖一个符号的完整范围时可以形成符号绑定；局部选择作为片段绑定，核心会在可确定时记住它所属的最内层符号。

一个功能绑定多处之后，右侧片段列表保留原始文件、行号和备注。点击片段会打开真实文件并高亮相应范围；不会把不同文件拼成一份看似连续的源码。

## 5. 从代码反查功能

把光标放入一个已绑定区域，右侧 **“当前代码属于”** 会列出相关功能，左侧也会高亮命中的功能。

当公共逻辑同时属于多个功能时，会显示多个候选。你可以切换功能，查看每个功能分别关联的其他片段。未绑定区域不会自动被猜测归入某个业务功能。

## 6. 审阅状态与版本确认

| 状态 | 含义 |
| --- | --- |
| 未阅读 | 尚未开始记录阅读进度 |
| 阅读中 | 正在分析该功能，可以随时返回继续 |
| 已确认 | 你已确认这组直接绑定代码、功能说明和相关备注对应的内容版本 |
| 待复核 | 已确认的证据或说明发生变化，或者存在失效/歧义锚点，需要重新查看 |

完成阅读后，在功能标题旁点击 **“确认已读”**。至少要有一个绑定片段，且不能有失效或歧义锚点。

确认操作会携带当前界面持有的内容摘要。若 Agent 在你读代码之后修改了源码或标注，后端会拒绝旧摘要的确认，并提示刷新后重新审阅；不会直接把最新、尚未核对的版本标成已确认。

**已确认只覆盖直接绑定证据。** 它不表示测试运行或通过，也不表示所有调用依赖、配置和运行条件都没有变化。你可以把相关测试和配置片段一起绑定，但这种关联仍不等于测试覆盖率。

纯粹在代码前面插入无关行、而已绑定内容本身保持一致时，工具可能只显示位置更新，并保留已确认状态。函数或文件重命名则可能需要重绑，因为身份变化不能被默认当作已经确认。

## 7. Agent 修改代码后的流程

1. 在原来的编码工具中让 Agent 完成修改。
2. 回到 CodeTrail，点击右上角 **“刷新代码与索引”**。
3. 查看“改动”列表和“需要复核”数量。
4. 打开“本次改动”，逐项查看新增、删除和修改。
5. 打开“相关逻辑”，查看调用位置、被调用定义和“可能受影响”的功能，再结合右侧片段核对原有行为。
6. 失效绑定先修复；确认当前实现后，再点击“确认已读”。

v0.2 **没有自动 watcher**。停留在应用里不会持续自动重读工程；使用手动刷新或重新打开工程更新索引。部分标注操作也会重新读取源码，但日常工作中建议在 Agent 修改后显式刷新。关系导航还会核验文件哈希，发现旧位置失效时会停止跳转并要求重新分析。

## 8. Git 对比怎么选？

### 查看未提交的最终代码

展开“本次改动 → 对比设置”后使用：

| 项目 | 输入 |
| --- | --- |
| 基线 | `HEAD` |
| 目标 | `WORKTREE` |

点击“比较”。这是基线提交到最终磁盘文本的比较，综合展示暂存、未暂存和未跟踪文件，不分别展示 index 与 working tree 两层。

例如，函数从 `return 1` 改为 `return 2` 并暂存，随后又改为 `return 3`，此模式比较的是 `1 → 3`。

### 查看两个提交

基线和目标都可以填提交 hash、分支或标签。例如基线 `HEAD~1`，目标 `HEAD`。输入无效版本时会返回明确错误。

历史文本来自所选提交；功能索引仍是当前工程保存的索引，因此历史功能关联需要人工核对。删除代码会保留旧侧文本，删除函数的影响由旧版本符号计算。

### 需要知道的边界

- 非 Git 目录仍能阅读、绑定和保存功能，但没有真实 Git diff。
- 没有第一次提交的仓库，`HEAD → WORKTREE` 使用空基线。
- Git 对比要求打开仓库根目录。打开子目录时会提示正确的根目录，阅读和标注可以继续。
- 功能影响依据修改行和直接符号/片段绑定计算，不是完整依赖传播。
- 对范围锚点和历史删除行，部分关联只能按已知行范围估计，界面会提示核对。
- 文件权限或路径变化可能出现零增删行；这不表示完全没有文件变化。
- 比较不执行 Git clean/textconv 过滤器。特殊转换、LFS 和自动换行转换可能使结果与命令行 Git 的归一化显示不同。

可以使用对比栏右侧的按钮，在并排与统一 diff 之间切换。

## 9. 锚点失效时怎样处理？

| 片段状态 | 建议操作 |
| --- | --- |
| 定位正常 | 按当前位置继续阅读 |
| 位置已更新 | 内容仍可定位，查看更新后的原文件位置 |
| 内容已变化 | 结合 diff 复查；如范围已不再表达原功能，重新绑定 |
| 锚点失效 | 原符号、文件或有效范围找不到；选择正确代码并重绑 |
| 定位有歧义 | 出现多个可能位置；人工选择正确位置并重绑 |

重绑步骤：

1. 切换到“完整代码”，打开正确文件。
2. 选中新的片段，或将光标放入目标函数。
3. 在对应旧锚点卡片上点击 **“重绑”**。
4. 核对对话框中的文件、行号和功能，确认。
5. 阅读后重新确认该功能。

重绑保留原锚点的身份；解除绑定则移除该关联。删除功能或解除绑定都不会删除源文件。不要仅为消除待复核状态而把不相关片段重绑进去。

## 10. 阅读记录在哪里？

真实工程中的持久化位置为：

```text
.reader/index.json
.reader/features/<feature-id>.json
```

功能名称、说明、代码绑定和审阅摘要按功能分文件保存。打开和刷新不会主动创建元数据目录；明确的标注或审阅操作才写入这些文件。

你可以自行决定是否把 `.reader/` 提交到版本管理。代码内容变化导致的“待复核”状态会在读取时重新计算，不要求刷新操作额外写一次状态文件。保留整个 `.reader/` 才能完整保留阅读成果。

内置演示使用 localStorage。底部“打开演示”只切换到示例，不会覆盖真实仓库的 `.reader/`。

## 11. 导出阅读记录

点击右侧的 **“导出阅读记录”**，查看 Markdown 文本。其中包含功能说明、绑定位置和当前阅读状态。

- 桌面版：预览后使用“复制内容”；若当前系统剪贴板不可用，可在文本区域手动选择复制。
- 浏览器演示：还可以点击“下载 Markdown”。

桌面版目前没有任意文件保存对话框。导出记录中的 Git 提交号是仓库 HEAD 信息，不能单独代表未提交工作区的完整快照；实际确认判断使用绑定内容摘要。导出也不等于测试报告。

## 12. 常见问题

### 浏览器里点“打开仓库”不能读取本机文件

`npm run dev` 打开的是内置浏览器演示。请运行 `npm run desktop`，在 Tauri 桌面窗口中选择目录。

### 列表中没有某些文件

先关闭“只看改动相关”和搜索条件，再展开底部提示。默认跳过隐藏项、项目忽略项、生成目录、虚拟环境和依赖目录；单个文件超过 2 MiB、非 UTF-8 或二进制内容也会跳过。

目录索引最多 10,000 个候选文件，累计源码达到约 64 MiB 时停止继续索引；Git 对比最多 2000 个路径，前后文本合计上限 64 MiB。超出时提示会说明尚有内容未分析。

### 能读某种语言，却没有符号列表

当前结构提取只实现 Python、Rust、TypeScript/TSX、JavaScript/JSX。其他可读取的 UTF-8 文件可以查看并绑定范围，但没有承诺其语义分析能力。语法错误也可能导致符号不完整，界面会提示。

### 函数改名后没有自动迁移绑定

这是保守处理。工具保留失效锚点，由你明确重绑，避免自动把旧阅读结论移到错误函数。

### 点击确认提示“代码或标注在阅读后发生变化”

说明版本校验发现当前内容与界面读取时不一致。刷新后查看改动，再确认；不要跳过这一步。

### `npm run doctor` 检查不通过

按提示补齐 Node.js 22.12+、Git、Rust/Cargo，以及平台开发依赖。Mac 需要 Xcode Command Line Tools。刚安装 Rust 后重新打开终端，让 Cargo 路径生效。

### 如何生成 Mac 应用？

在 macOS 环境运行 `npm run desktop:build`，构建输出见终端和 `src-tauri/target/release/bundle/`。本版已在 Linux 做原生编译与真实 WebView/IPC 验证，但没有提供已测试的 macOS DMG；Mac 打包、系统签名和分发仍需在对应环境完成。

### 可以让它自动解释代码、找所有调用方吗？

v0.2 提供 Python 静态调用与引用导航，以及可选 Pyright 语义增强。尚未接入模型、AI 自动总结、完整动态调用图或数据流分析；解析结果不会被当作运行时的完整证明。

## 13. 用“相关逻辑”继续追踪一次修改

### 推荐练习

1. 打开示例的“模型路由”，定位 `choose_route`。
2. 点击中间“相关逻辑”标签。必要时在“当前符号”下拉框中选择 `choose_route`。
3. “调用方”中可看到 `stream_chat` 和相应测试；点击调用位置可以看到实际传参。
4. “被调用方”中可查看 `Route` 的定义。图中只连接已解析目标，内建或外部边界另行显示。
5. “非调用引用”中查看 `get_route_callback`。它返回函数对象，此处并没有调用路由函数。
6. 在“功能影响线索”中查看“对话入口”：原阅读状态仍是“已确认”，同时出现“可能受影响”和具体调用证据。
7. 改选 `dispatch_plugin`，观察 `handler(payload)` 为什么无法静态确定目标。

局部图用于看清一跳关系；列表保存每一处调用位置。相同调用目标在图中合并成节点，但列表不会丢掉重复调用点。每侧超过四个节点时，继续在列表中阅读其余证据。

### 关系来源与未知项

| 显示 | 含义 |
| --- | --- |
| 语法证据 | 由捕获源码的 AST、词法作用域与导入绑定得到 |
| 语义证据 | 可选语言服务器在相同捕获源码上提供了可对应的定义或引用证据 |
| 未解析 | 当前信息不足以确定目标，例如运行时参数、下标取出的函数或动态调用 |
| 有歧义 | 存在多个候选或冲突，不能选一个当成事实 |
| 外部边界 | 目标位于当前仓库之外，不能提供仓库内定义跳转 |

“已解析”仍表示源码绑定，不证明某次运行的具体执行路径。装饰器、运行时改写、配置和外部依赖都可能限制结论范围。

### Python 语义增强

桌面真实仓库中可以点击“Python 语义增强”。首次分析会启动应用提供的 Pyright，完成后显示结果来源和可用状态；这不是 AI 模型调用，不需要 API key。

增强需要可找到本机 Node.js 22.12+。通过开发方式运行时，`npm ci` 会安装 Pyright；打包应用会携带 Pyright 脚本，但不会额外携带 Node 运行时。找不到 Node 时，可在启动前设置 `CODETRAIL_NODE` 为其绝对路径。

语义服务在隔离的临时目录分析捕获的 Python 文本，不执行你的 Python 工程，也不读取其虚拟环境或自定义语言服务配置。当前使用固定 Python 3.12 分析设置；因此自定义 import 路径、依赖环境或其他 Python 版本的特性可能没有完整语义信息。未成功启用时，静态关系仍可阅读，具体原因会显示在页面中。

当前语义增强最多捕获 256 个 Python 文件、合计 16 MiB；一轮最多核验 256 个定义位置、总预算 15 秒。达到预算会返回明确的部分可用或降级提示，不宣称已经分析完整工程。

### 旧关系和历史版本

关系页显示当前工作区的快照摘要。点击证据时会读取实际文件进行哈希比较，发现外部修改就停止导航；刷新关系后重新选择证据。

两个历史提交仍可进行 Diff，但关系页不会把当前工作区图当作历史图。点击“分析当前工作区”可以返回当前版本关系。已删除、重命名且失去当前身份的符号，其历史调用方仍需要另行分析。

## 14. 从 v0.1 升级

安装新版桌面应用后，重新打开原来的目标仓库即可。请先备份项目及 `.reader/`；现有阅读标注保持兼容，无需删除或重建。源码开发用户按 [技术与开发说明](TECHNICAL_GUIDE.md) 更新依赖后启动。

浏览器演示会保留旧版已保存的功能说明并补充新的示例功能。若真实示例目录已存在，`demo:init` 仍拒绝覆盖；使用新的目标目录体验 v0.2 示例。

阅读记录属于原项目目录，请保留该目录及 `.reader/`。新版本的关系分析不会自动修改人工 Feature 或原有确认记录。

## 从项目概览建立全局观

项目带有 Agent 维护的概览时，打开工程默认先看到项目目的、模块职责和核心运行路径。CodeTrail 自身提供“打开与展示、修改与交付、阅读与复核”三条路径。每一步说明做什么、由哪个模块负责，点击即可进入对应功能和代码；阅读后可从左侧“项目概览”返回继续。

这是一份有源码证据的阅读说明，不是运行追踪生成的调用图。步骤关联失效会明确提示，不会跳到另一个同名函数。旧项目没有概览时，仍直接进入功能阅读，不要求补齐数据才能使用。

### 大项目的相关逻辑

关系分析会先建立跨文件声明绑定，再逐文件处理调用和引用位置；测试目录不会因为排在前面就耗尽其他文件的关系预算，也不需要为查看业务代码而删除测试。结果优先保留选中符号及必要的一跳变更影响。

资源保护仍然有效：单个文件超过 50,000 个关系位置，或当前查询结果超过 50,000 条时，会明确提示实际截断的范围；其他文件仍继续分析。语法错误和嵌套深度限制会单独提示，不再把全局预算耗尽描述为后续文件的语法错误。可选 Pyright 增强还受独立候选和请求预算约束，不能消除静态证据的截断限制。任何不完整提示都不意味着未展示的调用者不存在。

## 右侧动态和我的批注

右侧“Agent 动态”只展示当前加载项目改了哪里、影响什么、预期效果和 Agent 报告的验证结果，不需要阅读代码差异。加载 local_model_chat 时不会显示 CodeTrail 的开发动态；程序执行与中间结果仍在“运行记录”。没有本项目修改报告时显示“暂无修改动态”，这不等于保证没有其他未上报改动。旧记录缺少明确项目归属时保留在磁盘但不自动展示。动态由 Agent 按协议主动报告，每 2 秒更新一次，不会打断正在阅读的页面；历史状态不代表 Agent 仍在线。

在项目概览、功能或源码中，随时点右侧“＋ 记批注”，输入不明白的地方或修改建议。选中源码再记批注会保留引用；不选中也可以直接写。停笔后看到“已自动保存”即已写入项目；失败时请保留草稿，返回原项目重试。“查看详情”会临时替换右侧面板，收起详情即可返回动态和批注。

在“我的批注”点击“导出 Markdown”，全部已保存批注会写入项目 `.reader/annotations.md`，界面会显示完整路径。你可以手动把文件发给 Agent。批注不会自动发送或被 Agent 自动清除，导出也不代表已经解决；源码变化后，记录中的位置和哈希仍代表批注时的版本。

## 用一次真实运行读代码

左侧点击“运行记录”，选一次实际执行。先看每一步的结果和“为什么”，再展开关键变量，需要时点击“查看对应代码”；返回按钮会带你回到原来选中的运行。若源码已变化，保留旧结果与当时片段，禁止把旧行号直接对应到新代码。

这里的“隔离测试执行”与“应用执行”会明确标注。当前聊天样例真实运行后台与 SQLite，模型为 DEMO 脚本，未执行浏览器或调用真实模型。日常程序只有接入采集器后才能记录，每次运行编号不同；缺少记录时阅读器不会自己猜测中间结果。接入说明见 RUNTIME_RECORDS.md。

## 搜索函数和变量

在左侧原有搜索框输入函数名或变量名，停笔后会显示“定义匹配”和“代码中的文字匹配”。点击结果直接打开文件并跳到对应行，不必先切换到文件列表。原有功能说明和文件路径筛选继续保留。

定义来自最近一次符号索引，主要支持 Python、Rust、C / C++、TypeScript / JavaScript；外部 Agent 修改代码后请刷新索引。变量、调用位置及其他语言通过不区分大小写的字面文字搜索查找，可能匹配注释，不表示已完成变量作用域或调用关系分析。文字结果跳转前核对源码摘要，版本不一致时需重新搜索。

搜索仅限当前项目，遵守忽略规则并排除生成目录、`.git`、`.reader` 和符号链接；不会启动 Git、Node 或被阅读项目。单次最多扫描10,000文件/64 MiB、每文件2 MiB并返回200条文字结果，定义最多展示40条。达到限制或文件读取不完整会显示提示，不能用“未命中”断言代码不存在。

C/C++ 的函数、类、命名空间和宏可由新版 CLI 建立功能关联，重载请按签名和实际符号 ID 区分。`.h` 会在 C 语法不完整时尝试 C++ 解析。这里提供语法定义阅读，不展开宏或认定条件编译分支；调用者分析仍主要支持 Python。请使用0.3.1或更新的CLI和桌面版本配合，旧0.3.0工具不包含这些解析器。
