# v0.2 实现范围与技术决策

本版本围绕“改了哪里、与谁相关、证据在哪里”升级。它继续使用 Rust + Tauri + Monaco，并在 v0.1 的功能索引、Diff 与版本审阅上增加 Python 关系导航；不代表原始开发 brief 的全部里程碑已经完成。

## 能力与范围

| 能力 | 实际行为 |
| --- | --- |
| 声明索引 | tree-sitter 提取 Rust、Python、TS/TSX、JS/JSX 的语法定义与范围 |
| 功能索引 | 人工 Feature、多文件锚点、反向查找、显式重绑、阅读记录 |
| Git | 提交到最终工作区、提交到提交、真实行差异与直接符号关联 |
| Python 关系 | 从当前捕获源码构建词法绑定和导入关系，返回一跳调用和函数值引用 |
| 关系来源 | 标明语法绑定或可选语言服务结果；未知、歧义与外部目标单独展示 |
| 局部图 | 以选中符号为中心的调用方/被调用方；每侧最多四个节点，其余证据仍在列表中 |
| 可能受影响 | 已解析调用的目标发生变化时，提示直接调用方所属功能并给出代码位置 |
| 审阅保护 | 阅读状态只由直接绑定证据和人工操作控制；依赖影响不会覆盖该状态 |
| 快照保护 | 返回源码摘要与文件哈希；分析期间变化会被拒绝，证据导航前再次核验 |
| 可选 Pyright | 使用应用提供的固定依赖，以临时捕获工作区运行；缺失或超时则降级 |

## 明确不作出的结论

- 一条源码调用边不证明它在某次运行中执行。
- 一条函数值引用不被当作直接调用。
- 同名符号不会仅因名称相同被连接；动态 receiver、反射、运行时注册和无法确定的绑定保留未知。
- “可能受影响”不表示行为一定改变或已经存在 bug。
- 测试引用或绑定不表示测试运行、通过或覆盖率。
- 当前工作区图不表示修改之前或其他历史提交的关系。
- “未发现已解析调用方”不表示“绝无调用方”。

## 语义增强的边界

语言服务器只接触应用捕获并写入临时目录的 Python 文件与受信任的分析依赖，不使用仓库中的可执行配置或虚拟环境解释器。Node 的权限限制禁用子进程、原生扩展等能力，并限制可访问文件；应用不会通过该路径运行用户工程。

分析环境与工程实际运行环境可能不同。因此依赖自定义导入路径、第三方环境、条件安装或动态注入的关系可能不完整。语义结果还需要映射回已捕获的源码符号，才能成为可点击的仓库内定义。源码在分析期间变化时，结果不得继续作为当前事实使用。

只读默认策略会牺牲一部分环境补全能力，换取可预测的源码阅读边界。语言服务是按需增强，不是打开仓库的前置条件。

## 旧版兼容与持久化

`.reader/index.json` 与 `.reader/features/<id>.json` 的 schema 保持 1。关系结果由源码重建，不修改既有人工 Feature。阅读确认仍使用直接绑定内容及说明的摘要，并校验界面提供的 `expectedDigest`。

原来的完整符号、符号内子范围、普通范围锚点和失效状态仍然有效。函数或文件重命名不会默默迁移旧确认；用户仍需检查并重绑。
