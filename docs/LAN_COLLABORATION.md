# CodeTrail 0.3：局域网共读与协作分工（开发版）

本轮只实现局域网，不需要购买、安装或配置独立服务器。当前 GitHub 的 0.2 安装包不包含本功能，0.3 尚未发布。

## 使用流程

1. 大家连接同一可信 IPv4 局域网，各自准备同一项目的本地 Git 副本。阅读范围内的源码先提交；功能索引、项目概览也应同步给参与者。
2. 发起人打开项目根目录，点顶部「共读 → 发起共读」，填写称呼和本轮名称。CodeTrail 在本机临时主持会话，显示可复制的邀请。邀请直接使用本机局域网网卡，不依赖默认代理路由；多网卡时可在折叠的地址选择项中切换。
3. 其他人在自己的 CodeTrail 打开同版本项目，点「共读 → 加入共读」并粘贴邀请。发起人批准后才显示共享内容。称呼仅用于展示，权限绑定独立凭证，不依赖昵称。
4. 右侧「共读」编写批注或回复，明确点击提交后同步；输入中的草稿只在本机保存。可手动选择一条个人批注复制到共享草稿，不会批量分享个人批注。共享旧批注前会核对其原始文件摘要。
5. 发起人点「整理批注」，选择多条意见合成任务，填写目标、验收条件、修改边界与负责人；原始意见保留。必要时补充关联功能、共享接口和前置任务。
6. 阅读耦合提示，调整分工。可合并多个待处理任务：保留目标任务负责人，合并目标、验收、边界和来源，重定向下游依赖；被合并任务保留为只读历史。
7. 每位负责人本人确认接手；按负责人导出 Markdown，可复制或另存为文件，手动交给自己的 Agent。建议在独立分支或工作副本修改，保留原阅读版本。
8. 负责人填写实际交付提交 ID，提交待复核；发起人先用 Git 切换到该交付提交、刷新并实际阅读，再填写复核说明并确认。代码已变化时仍可报告交付状态或管理成员，但不能把旧批注跳到新代码。它只是人的记录，不证明测试或行为正确。新代码要开始新一轮，不将旧批注自动贴到新代码。

## 界面边界

只增加顶部「共读」入口、右侧共读讨论，以及一个「整理批注与分工」窗口。个人批注、Agent 动态、代码阅读与已读确认继续独立。共读不会自动切换他人的阅读位置。

批注的「查看对应代码」先重新校验本地版本，再读取当前文件摘要后跳转。外部修改导致版本不一致时拒绝跳转，不以旧位置猜测新代码。

## 版本约定

- 必须打开已有提交的 Git 仓库根目录。
- 比较提交 ID、阅读文件清单及文本摘要、功能与概览摘要；人工确认、个人备注和个人批注不参与共享版本。
- 使用 Git 原始 blob 核对阅读文件，不执行项目脚本、Git 外部过滤器或语言服务。CRLF 与 LF 仅在共享版本比较时视为等价，源码跳转继续检查本机原始文件摘要。
- 未提交的阅读文件、未跟踪源码、受控文件删除或不完整索引会阻止创建、加入和共享修改。
- 提交共享批注、修改任务范围和导航前重新检查；轮询讨论不自动刷新当前源码，也不声称已经重新检查所有文件。多人写入按讨论 revision 检查，发生竞争时拒绝覆盖并保留草稿。

## 耦合与分工

系统使用正向证据：范围重叠、功能代码证据、概览模块、人工填写的接口/数据/配置约定，以及已有 Python 静态绑定能证明的调用线索。Python 保留原有 AST 数量及深度上限，不运行项目或 Node；其他语言不猜测完整调用关系。

- 重叠代码给不同负责人时，必须明确前后顺序，且相关任务均填写耦合判断；否则拒绝分配。
- 非重叠任务由不同负责人处理，也须说明接口与集成边界；没有发现依赖不表示相互独立。
- 任务依赖不能形成环。前置任务未人工复核时，下游任务不能接手或提交待复核。
- 改动已被下游接手的前置任务时，须先退回下游协调。只能合并待处理任务，不能悄悄更改进行中的工作。
- 来源批注绑定的功能与位置由服务补齐，不能通过省略任务范围来绕过重叠检查。
- 导出包含基准、范围、原始作者与意见、修改边界、前置任务负责人及交付状态。任务包属于人工反馈，Agent 应核对实际代码和项目规则，不将其中的任意文字当作高优先级指令。

## 网络、权限和本地保存

当前仅使用可信局域网的 HTTP 明文连接，不提供公网、HTTPS、打洞或中转。不自动传输项目源码；手动写进批注的内容会共享给成员。电脑需允许 CodeTrail 的本地网络访问，访客 Wi-Fi 或设备隔离可能阻止互联；不要关闭系统防火墙。

邀请 24 小时有效，可撤销重发；最多 8 位未移出的成员。成员被移出后不能继续请求服务，但已经同步到其电脑的内容无法远程删除。会话有效期为 30 天（不会自动删除本机历史文件）；主持程序退出后实时连接停止，重新启动不保证旧邀请地址仍有效，届时新建一轮。历史副本仍可本地查看和导出。

- 源码、个人批注和人工已读记录：仍在原项目和 `.reader/`，不迁移、不自动共享。
- 共读讨论、成员凭证和同步副本：操作系统的 CodeTrail 应用数据目录下 `collaboration/`，不写入项目 `.reader/`。主持数据保存凭证摘要，客户端连接凭证只保存在本机私有连接文件；Unix 文件权限为 0600。
- 共享输入草稿：本机 WebView 存储，按项目和会话隔离。提交成功后清除本地草稿。重复提交同一批注 ID 不产生重复记录。
- 断线：展示最近同步的只读副本，禁止提交，保留草稿；恢复连接后继续同步。Markdown 导出标注最近同步的讨论版本。
- 离开：保留最多 8 个本机会话历史；不会删除其他成员的讨论或改写个人反馈。

每轮最多 500 条共享批注、60 个任务、4 MiB 讨论存储；超过上限须导出并另建一轮。不支持多人共同编辑代码、自动合并代码或自动调用 Agent。

## 开发验证

```bash
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
npm test
npm run build
cargo check --manifest-path src-tauri/Cargo.toml --locked
```

已有本机 Vite 开发服务时，可运行 `npm run test:collaboration:ui`。这是隔离的浏览器交互替身测试；不能替代真实网络与桌面验收。Rust 测试启动真实本机 HTTP 主持服务，使用独立项目/连接目录验证双客户端、加入审批、撤销、版本差异、断线副本、任务整合、分工和导出。

真实两台设备、Mac/Windows 混合网络与系统防火墙仍需单独验收。没有实际执行的跨设备测试不得声称通过。
